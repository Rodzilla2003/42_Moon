# Перелёт к Луне и выход на орбиту

Готовый сценарий на основе GOAT и его закреплённой версии 42. В архив уже включена папка `42`: отдельно скачивать подмодуль не нужно.

Расчёт начинается после импульса ухода с околоземной орбиты высотой `400 км`. Через `4,5 суток` аппарат подходит к Луне на высоту `300 км` и выполняет тормозной импульс около `791 м/с`. Затем рассчитываются более шести витков. Старт с поверхности Земли не моделируется.

## Запуск через Qt Creator

1. Распаковать весь архив, например в `C:/42_Moon_GOAT`. Сохранить папки `42/Model`, `42/World` и `examples` на своих местах.
2. Открыть `42support/42.pro` и выбрать комплект `Qt 5 MinGW` с установленным компилятором. Код использует `Qt 5.12` или новее. Комплект MSVC для приложенных библиотек не подходит.
3. В настройках запуска указать рабочий каталог: папку `42` внутри проекта.
4. В параметрах командной строки указать `../examples/LunarCapture` без одинарных кавычек.
5. Собрать проект, нажать зелёную кнопку запуска в Qt Creator, затем «Старт» в окне программы.

Программа называется `42sh_moon`. Она появляется в каталоге сборки `bin/<разрядность>`. Проект собирает `GLEW` из исходников, выбирает подходящий `FreeGLUT` и копирует его DLL к программе. Не подменять эти библиотеки файлами другой разрядности. В настройках запуска Qt Creator должна быть включена штатная опция добавления библиотек комплекта в `PATH`.

Окно Qt показывает высоту, скорость и удельную энергию относительно Луны, а также проекцию орбиты после захвата. Для высоты используется `log10(h / км)`. Кнопка «Пауза» останавливает расчёт, «Продолжить» возобновляет его. После завершения графики и 3D сцена остаются открытыми. Для нового расчёта перезапустить программу.

## Отрисовка орбиты

В `42/Source/42gl.c` условие изменено на `if (E->rmin > 0.005*O->Radius)`. Порог `0.005` позволяет видеть опорную орбиту при большем удалении камеры. `Orrery Window Exists` включён в `Inp_Graphics.txt`.

В строке `12` файла `Orb_LEO.txt`, у `J2 Drift`, стоит `TRUE`, как в присланной настройке. По коду `DrawOrrery` этот флаг не является общим выключателем отрисовки. Он задаёт дрейф опорной орбиты. Поступательное движение нового сценария считает отдельный интегратор без `J2`; он обновляет опорную орбиту для показа по рассчитанному состоянию.

Окно `Orrery` сначала показывает систему Земля–Луна. После торможения оно приближается к Луне и показывает орбиту в её плоскости; центром опорной орбиты становится Луна. График в Qt показывает лунную орбиту сразу после захвата независимо от масштаба 3D камеры.

## Модель и файлы

- `lunar/moon_core.c` — интегрирование движения в геоцентрических эклиптических осях: точечная Земля и движущаяся Луна с дифференциальным ускорением начала системы. Эфемерида Луны — штатная `LunaPosition` из `42`, вариант `MEAN`.
- `lunar/moon_mission.c` — начальное состояние, мгновенный импульс, перевод представления к Луне и телеметрия.
- `lunar/moon_exec.c` и `moon_glut.c` — подключение расчёта к `42`, обработка Qt и сохранение окон после окончания.
- `lunar/qt_main.cpp` — четыре графика. Штатная динамика `42` продолжает считать угловое движение.
- `examples/LunarCapture/MoonMission.txt` — эпоха `TT`, время торможения, признак включения импульса, начальные положение и скорость. Координаты — геоцентрические эклиптические, метры и метры в секунду. Дата в `Inp_Sim.txt` должна совпадать с решением: программа проверяет эпоху.
- `lab/Отчет_НИР_Лунная_орбита.docx` — присланный отчёт с добавленным разделом о выходе на орбиту. Исходный документ сохранён в `lab/source`.
- `lab/results` — графики, телеметрия трёх запусков и результаты проверок.

Идеальные импульсы меняют скорость мгновенно. Расход топлива, реальный двигатель, солнечная гравитация, атмосфера и несферичность гравитационных полей не моделируются. Старые алгоритмы `42add/orbControl.c` для околоземного сближения сохранены, но в этом сценарии не выполняются.

## Сборка через CMake

Открыть `42support/CMakeLists.txt` в Qt Creator либо выполнить из корня проекта:

```text
cmake -S 42support -B build -DQTPLOT=ON -DGUI3D=ON
cmake --build build --config Release
```

Для численного расчёта без окон:

```text
cmake -S 42support -B build-numeric -DQTPLOT=OFF -DGUI3D=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-numeric --config Release
```

Запускать программу из папки `42`, передав `../examples/LunarCapture`. В Linux для 3D нужны установленные библиотеки `OpenGL`, `GLU` и `FreeGLUT`. В macOS используются системные фреймворки. Режим времени `NOS3` в новой сборке не поддерживается; использовать `FAST` или `REAL`.

## Воспроизведение проверок

Установить зависимости из `lab/requirements.txt`, затем из корня проекта:

```text
python lab/verify_mission.py --binary <путь-к-собранной-программе>
```

Проверяются основной сценарий, пролёт без импульса и уменьшенный шаг. Каждый запуск использует отдельную временную копию сценария.

Для повторного подбора начальной скорости:

```text
python lab/shoot_launch.py --library <путь-к-moon_solver> --write-case
```

Библиотеку `moon_solver` собирает CMake. Её файл называется `libmoon_solver.dylib`, `libmoon_solver.so` или `moon_solver.dll` в зависимости от системы. Подбор использует уже найденное решение как начальное приближение и сохраняет сценарий только после сходимости.

## Что проверено

Численный сценарий и контрольные запуски выполнены на macOS. Интерфейс `Qt 5.15.19` собран и запущен: графики получены из настоящего расчёта. Вариант с Qt и 3D собран; интерактивная 3D сцена и запуск Windows MinGW не проверялись.

На рассчитанном участке после захвата получено около `6,2 витка`, высота `298,46–301,80 км`, эксцентриситет меньше `0,001`. Это проверка примерно `14,2 часа` полёта после захвата, а не гарантия долговременной устойчивости.
